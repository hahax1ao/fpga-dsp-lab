# 学习路线与能力依赖

状态：路线与[M0 诊断流程](../diagnostics/README.md)已建立，四项学习任务尚未启动。各阶段可交叉推进，不设固定日历；根据 M0 证据跳过已掌握内容，按实际薄弱项补强。

| 里程碑 | 目标 | 依赖与进入条件 | 验收证据方向 |
|---|---|---|---|
| M0 能力诊断 | 检查理论、RTL、TB、Vivado 与 DSP 建模 | 用户选择诊断范围与交互方式；阶段 D 准备具体说明 | 独立成果、口头或文字解释、运行记录；不足项形成补强建议 |
| M1 工程基础 | Verilog、FSM、握手、FIFO、BRAM、DSP48、流水线、验证、XDC、STA、CDC、ILA | M0 相应领域证据；不要求先完成全部 M0 | 仿真边界与异常覆盖、约束与时序解释、必要上板证据 |
| M2 DSP 与数值基础 | 采样、卷积、Z 变换、FIR/IIR、DFT/FFT、定点、量化、复数、同步与均衡 | 先进行 DSP 摸底；可与 M1 并行 | 推导与解释、独立浮点模型、误差及频谱分析 |
| M3 算法 FPGA 部署 | 浮点→定点→硬件架构→仿真→实现→优化 | 对应算法 M2 能力与 M1 接口/验证/时序能力 | 对齐模型与 RTL 的数值证据、延迟/吞吐量、资源与时序、必要板测 |
| M4 实时综合系统 | 需求、架构、验证、优化、上板与复现交付 | 若干基础模块与 M3 算法部署已验收，再共同选题 | 可追溯需求、系统验证、实时预算、实物与复现记录 |
| M5 PS+PL 与科研进阶 | AXI、DMA、DDR、PS 控制与高吞吐 DSP | 按研究方向选择；先具备相关 M1/M3 能力 | 数据搬运正确性、带宽/延迟、缓存一致性与系统集成证据 |

## 依赖关系

- M0 分领域决定 M1、M2 补强；M1 与 M2 可以交叉进行。
- M3 的每项任务依赖其对应算法、定点知识与硬件基础，不要求机械完成全部前置章节。
- M4 候选为实时频谱分析、通信接收链或光通信 DSP 子系统，尚未选定。
- M5 可为 M4 提供搬运与控制支持，但不得把尚未验证的 DDR 延迟引入实时路径而忽略预算。

## 部署训练的证据链

需求及吞吐/延迟预算 → 浮点参考 → 定点与误差预算 → 接口和硬件架构 → RTL 对比验证 → 综合与布局布线 → 资源/STA/CDC 检查 → 必要上板及系统验收。

HDL Coder 与官方 IP 可作为后续指定工具，比较手写和生成架构时记录来源、配置、版本和可复现流程。HDLBits、LeetCode C++ 作为补充练习，不用题量代替工程能力证据。具体任务的验收标准在启动前明确。
