# M0-002：握手流水线 RTL 与自检 TB

- 类型：诊断；里程碑：M0；状态：todo。
- 更新日期：2026-10-12；交互方式：未选择，默认独立练习。
- 目标：核验独立 RTL、接口协议、算术位宽、流水线及验证设计。
- 先修：基本 Verilog 与同步时序；M0-001 不是强制先修。

## 需求与约束

由用户独立设计单时钟模块，将每次接收的两个有符号 16 位整数相加，输出精确的有符号 17 位结果。语言用可综合 Verilog；TB 可用 Verilog 或 SystemVerilog。

接口语义：输入 `a`、`b`、`in_valid`、`in_ready`，输出 `sum`、`out_valid`、`out_ready`，时钟 `clk` 与同步高有效复位 `rst`。数据仅在上升沿 valid 与 ready 同时为 1 时成交。rst 为 1 的上升沿优先执行复位，不计输入/输出成交，清除全部未输出交易；复位沿之后 out_valid 必须为 0，复位期间输入不被接收。

- 输出按接收顺序出现；每次成交对应一笔正确结果，不丢失、不重复。
- 下游停顿时，已有效的输出数据及 out_valid 保持，直至成交或复位。
- 模块至少有一级数据寄存，不允许输入算术结果纯组合直通输出。
- 无停顿稳态下可每拍接收一笔、输出一笔；允许流水线灌入延迟，但需声明无停顿延迟与测量方式。
- 若输入在第 k 个上升沿成交，最早输出成交为第 k+1 个上升沿。停顿时延迟可变，需说明保持/背压行为。
- 不使用厂商 FIFO/算术 IP 代替此次手写练习，不要求特定内部结构或固定寄存级数。对复位、吞吐及停顿均需解释。

## 用户交付

实际成果尚无。开始后在本目录按需保存手写 RTL、TB、自行设计的检查逻辑、运行方法与结果说明。记录模拟器版本、源文件、启动方法及是否使用提示；不要求 Agent 创建构建脚本。

TB 应自动比对成交结果并明确报错；同时覆盖连续输入、输入空隙、连续背压、背压解除、正负及边界运算、流水线有未输出交易时复位。若采用随机激励记录种子；仅使用确定性激励也可，只要能说明边界覆盖。TB 自身须遵守接口协议，避免时钟沿驱动/采样竞争。

## 验收标准

1. 接口、复位和无停顿延迟声明明确，可解释位宽及符号处理；没有意外锁存器或未定义输出消费规则。
2. 自检 TB 能发现数值错误、顺序错误、丢失、重复和停顿时输出变化；可通过用户自行选择的一处临时错误或独立失败用例，证明检查能报错，修复后保留前后证据。
3. 正常与边界测试零未解释失配；交易计数与清空过程有记录。不得仅凭一张波形认定通过。
4. 用户解释至少一段背压与一段中途复位行为，以及每拍吞吐的证据。
5. 如环境不能运行仿真，静态评审可先进行，动态项标未核验；环境受阻不判能力 L0。充分失败证据也可以完成诊断记录，功能未通过需明确标注。
